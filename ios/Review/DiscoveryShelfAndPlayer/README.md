# 发现卡片、关注列表与音乐播放器布局

Android 0.1.42（43）、iOS 0.1.0（44）、macOS 0.1.17。

## 改动

- iOS 和 Android 音乐播放器打开时显示用户选择的黑胶或封面样式，歌名、歌手在下方。点击大封面进入歌词；歌词页顶部固定小封面、歌名、歌手，点击小封面回到原样式。保留切歌拖动预览、歌词单独确认定位、点赞、评论、更多与全局音质。
- 修复独立插件无法从播放器进入作者主页的问题：按当前播放资源的插件调用现有 `artist({id, offset})` 目录协议，使用通用目录分页和曲目操作，不复制平台接口。插件需提供曲目的作者 ID 和作者目录能力。
- 三端发现卡片按可见宽度从左到右填满第一行，再进入第二行；最多两行横滑。少量资源不强制分成两行，点击卡片保留栏目完整队列。
- 关注/作者目录保留图片请求头，显示 52 点头像、名称和完整换行介绍。触底追加下一页，失败可原地重试，避免续页循环。修复独立栏目“更多”跳过第一页的问题。
- 三端外部插件歌单详情移除顶部“播放全部”；点单曲仍建立全部已加载曲目的队列。本地资料库操作保留。

## 问题来源

用户提到网易云的关注截图实际为哔哩哔哩关注 UP 主。已对照独立插件的真实返回：头像、介绍和 `morePage` 都有提供；缺图和续页导航问题来自 App 通用目录层。网易云插件没有声明该关注入口。本轮修复通用渲染/分页，适用于所有采用同一契约的插件，无需为每个平台重复发布插件。

## 验证

- Go 全量、插件宿主测试、MyGo vet 通过，macOS arm64 构建成功。发现卡片数量与宽度、关注触底/重试/作者入口、插件歌单单曲建立完整队列回归连续五轮通过，使用 MM_FRAMES 输出桌面截图。
- Swift 全量 223 项、Android JVM 168 项通过。Android Release lint 为 0 errors、41 warnings；iPhone/iPad 通用 Release 和 Android Release/Debug/AndroidTest 构建成功。
- Android 四项交互连续五轮通过：发现卡片次序和队列、黑胶/歌词/独立插件作者页往返、关注头像/介绍/触底分页、刷新替换两行数据。测试窗口检索明确启用多交互窗口，正确读取作者弹窗关闭后的主页面。
- iPhone 四项交互连续五轮通过（20 次），iPad 同四项通过。验证歌词顶部固定、返回黑胶样式、作者主页、左右切歌、歌词独立确认与换歌清除选择，及发现卡片/关注续页；截图使用隔离插件和本地演示数据，真实平台账号请求未逐项验收。

## 设备覆盖

Android 已无线保留数据覆盖 0.1.42（43）：新旧 APK 原签名证书一致，16 KiB 对齐正确，首次安装时间未变，启动成功。Release 无法 run-as，未读取 Android 私有数据摘要。

iPhone 已无线保留数据覆盖 Build 44：安装前独立备份，安装后 114 个资料与设置文件规范化摘要相同。系统因锁屏拒绝自动启动，尚未在真机手动验收播放器操作。没有卸载、清数据或整域覆盖。
