# 移动端视频取流、调度与预加载

Android 0.1.39（40）、iOS 0.1.0（41）；独立 YouTube 插件 0.2.7。

## 改动与边界

- iOS 在校验 Content-Range、编码和内容标识后，每 16KiB 持续供数，不再等整块 256KiB 下载完成。共用进行中的块，最多两个 Range 请求和 4MiB 块缓存；取消停止网络任务。长度不符或内容变化立即中止，不把已发送前缀混入重试响应。
- 两端目录和播放各有一个 QuickJS VM，在同一 actor / 串行 dispatcher 上访问共享宿主存储。每个 VM 仍串行、保留预算和权限校验；取消目录不销毁播放 VM。登录、退出和配置变化使播放 VM 失效。
- 下一条只准备 256KiB，不启动解码器或第二条音轨；只在当前稳定播放且达到 70% 时运行。容量一条、寿命 90 秒；队列、会话、画质、暂停和缓冲变化取消或使交接失效。打开时复用首块。已有当前音乐对应的静音视频预载保留。
- 安卓以 0.97 / 1.03 倍速修正小幅漂移，较大漂移才 seek，并限制连续校正频率；显式 seek 复用当前解码器。
- 宿主提供通用网络和近期缓冲提示，格式选择仍由外部插件实现。YouTube 自动模式在未知网络从 720p 起步，流量受限或近期卡顿时优先不超过 480p，并按有效带宽留出余量。手动画质不被覆盖。音频、视频、字幕短期复用播放器响应；同种解析再次请求时刷新地址，以保留坏地址恢复能力。

## 可重复基准

测试片为 14 秒、640×360、30fps、H.264、约 1.81Mbps，文件 SHA-256 见 `fixture-sha256.txt`。限速约 1.31Mbps、响应延迟 80ms，因此该固定码率本来就高于可用带宽。首帧必须来自 AVPlayer 视频输出 / ExoPlayer 的真实渲染回调。

| iOS macOS 原生播放器基准 | 修改前 | 修改后 |
| --- | --- | --- |
| 三次冷加载首帧（ms） | 1872.76 / 1678.60 / 1678.68 | 245.61 / 208.48 / 210.02 |
| 首帧中位数 | 1678.68ms | 210.02ms |
| 第一条播放 9 秒内卡顿 | 1 次 / 6.864s | 1 次 / 6.847s |
| 进程峰值 RSS | 80,789,504 bytes | 80,281,600 bytes |
| 进程 user + system CPU | 1.099s | 0.826s |

上述内存与 CPU 是独立测试进程的单轮测量，含框架开销，不代表真实 YouTube 流量、手机续航或统计显著差异。固定高码率场景的卡顿没有实质改善，不能宣称已消除卡顿。

iOS 首块预备后的三次首帧为 280.16 / 26.11 / 16.19ms；后台准备分别花费 1662.25 / 1643.88 / 1654.58ms。预载把准备工作提前，不消除它的网络成本。安卓同媒体、同限速的原生冷加载与首块复用数据见 `android-performance.json`；它比较当前二进制的两条加载路径，不是旧发布版的整体性能对照。

运行方式：启动限速 Range 服务器后，将 `MB_VIDEO_BENCHMARK_URL` 与 `MB_VIDEO_BENCHMARK_RESULT` 传给 `swift test --package-path ios --filter videoPerformanceBaseline`；`videoPreparedPerformance` 单独运行，避免争抢带宽。Android 将同一 MP4 放进 `android/app/build/generated/video-fixture/video-performance.mp4`，重新生成 AndroidTest 包，通过 `-e mbVideoBenchmark true` 执行 `VideoPerformanceDeviceTest`。默认回归不运行这两个基准，不提交大体积测试视频。

## 回归与截图索引

- Swift 全量 215 项；分段、并发队列及首块复用四项新行为连续五轮通过。默认原生预加载失败后的清理线程另有专门回归。
- Android JVM 164 项；46 项插件 / 流播放设备回归通过，四项关键原生行为连续五轮通过。Release lint 0 错误、39 个既有警告。
- iPhone、iPad 的真实视频返回 / 展开与后续视频画质沿用共四项 UI 回归通过，Debug 与通用 iPhone / iPad Release 构建通过。
- 初轮发现安卓暖播放器展开仍触发暂停，统一了追时钟与展开阈值。iOS 初轮发现预加载默认异步回调的清理操作丢失主线程隔离；已明确声明回调的 MainActor 类型，并通过原生错误路径和两类设备 UI 回归。

## 真机交付

Android 原证书覆盖安装 0.1.39，首次安装时间未变。iPhone 已覆盖 Build 41，安装前后 126 个私有文件的规范化摘要一致，均启动成功。没有卸载、清数据或覆盖整个应用数据目录。真实平台的弱网、长时播放和电量收益尚未测量。
