# 移动端刷新与视频画质验收

Android 0.1.31（versionCode 32）/ iOS、iPadOS 0.1.0 Build 32。

发现页下拉先清除目录缓存，再等待首页与独立导航栏目的请求完成后更新内容。错误保留已有内容并显示重试入口。iOS 首页使用绑定到自身滚动容器的刷新控件，短页面也可下拉；横向卡片不接管垂直回弹。安卓刷新期间忽略旧请求的迟到响应，工具栏与下拉共用刷新入口。

画质选项来自插件实际返回的媒体信息。选择保存到本地，当前视频重载保留进度与播放意图，后续视频及重启继续沿用。某条视频缺少首选画质时临时回退，并显示实际画质，不改写偏好；设置可重置为自动。视频画质与音乐音质分别保存。

## 验证

- Android JVM 158 项、lint、Debug、设备测试包、Release 构建通过。真实下拉及画质菜单各连续五轮通过；另通过真实 ExoPlayer 切画质保留暂停位置、下一视频沿用偏好、音频模式视频预载和 QuickJS 画质契约三项设备回归。
- Swift 全量 199 项通过，包括真实插件脚本的刷新调用计数、画质参数与返回解析、设置重新加载、回退不覆盖首选画质、重载保留进度与暂停意图。
- iPhone 与 iPad 的画质切换各连续五轮通过。初次下拉回归暴露手势未触发，修正滚动容器后两种设备的真实下拉各连续五轮通过；没有使用失败重试。截图取第五轮。
- iPhone 与 iPad 各通过一次真实 AVPlayer 视频返回、浮窗与展开回归，每次往返三轮，保留此前的卡死修复。两种设备构建与真机 Release 构建通过。
- YouTube 外部插件 0.2.2 的 29 项 Node 回归通过。经当前网络代理实测公开视频返回 1080p、720p、480p、360p、240p、144p，默认 1080p 媒体地址的范围请求返回 HTTP 206；不同视频仍受平台实际提供的格式限制。
- 正式 APK 使用原签名并通过包名、版本及 16 KiB 对齐检查。公开 iOS 资产为未签名 IPA，真机覆盖使用同一源码的签名 app。共记录 337 份生产文件哈希，用于核对构建与提交源码。

尚未在用户账号下遍历所有插件、全部 YouTube 视频或系统画中画恢复路径。
