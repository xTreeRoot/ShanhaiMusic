# 播放器、下一首预加载与账号兼容

2026-11-20，产品版本 0.1.0（23），宿主兼容版本 0.1.27。

播放器全屏展示，取消底部额外留白，保留 Home 指示条安全区和“从封面展开”设置。随机/循环操作显示中文反馈，底部提供歌词、评论点赞、音频输出和待播清单的小字。横屏提供歌词、律动、待播清单、选歌和评论，评论区不重复展示曲目信息；选歌与队列直接控制当前播放会话，评论复用现有分页与点赞能力，律动沿用逐字时间，并遵循减少动态效果设置。

音乐和视频使用统一的细进度条，圆点默认 9pt、拖动 12pt，触控区仍为 44pt。视频画面单击切换控制条，双击播放/暂停；播放中 4 秒无操作收起，暂停、拖动和继续操作会取消旧收起任务。普通页和全屏使用同一套手势。

播放到 70% 后，准备自动播放顺序中的下一首，只解析地址和预读首个 256 KiB 分段，不创建第二个播放器、不提前播放、不改变当前曲目。切歌复用同一 RemoteMediaAsset 的分段缓存；90 秒后不复用旧准备，载入失败重新解析。修改队列、随机/循环、音质、切源、暂停、拖回阈值之前或视频接管均取消预备任务。预取失败保持静默。

YouTube Music 0.1.6 将 OAuth 账号验证改为官方 YouTube Data API `channels.list(part=snippet,mine=true)`，避开实际返回 HTTP 400 的网页 `account/account_menu`。官方合同对照 googleapis/google-api-go-client 的 youtube/v3/youtube-api.json；无频道和 API 失败明确报错，不保存未验证会话。用户已确认新版 YouTube 授权登录成功；个人音乐库继续使用上游接口，尚未独立验收。

汽水音乐从 0.2.2 更新到 0.3.4。已加入账号、个人歌单及扫码切换 App 后的有限断线恢复。0.3.2 真机脱敏诊断确认：扫码确认接口先出现 -1005，恢复后返回业务错误码 2156，尚未请求账号资料。

0.3.4 曾按公开参考 qishui-api 的 Passport 合同及通用二维码文案提示使用抖音 App；真实匿名取码和等待状态正常，但用户完成授权后仍返回 7。后续静态核对汽水官方 3.7.0 客户端，确认它要求使用汽水音乐 App，必须将通用取码响应包装成 `/light/invoke/scan_login` 专用入口；扫码票据与轮询票据分别使用，不能混用。因此 0.3.4 的通用文案判断已被官方实现纠正。0.3.5 改用专用入口后，用户确认汽水正确识别 Windows / 山海二维码，但完成确认仍返回 2156；0.3.6 补齐本机匿名设备注册后仍返回 7，尚未读取账号资料。

build 22 修复宿主的两处缺口：fetch 原先忽略 `redirect: manual`，会自动跟随跳转；现在单跳 transport 交由运行时按 follow/manual/error 执行，manual 将 3xx 与会话响应头交回插件，follow 每跳核对网络权限，保留现有重定向方法和凭据规则，最多 10 跳。扫码二维码出现后申请 iOS 短时后台执行，成功、失败、取消均释放；系统时限到期时取消当前扫码，拒绝旧响应，提示回到山海重新登录。系统 OAuth 登录不申请这项扫码保护。用户使用 build 22 后仍反馈请求频繁，这两处修复未解决完整授权。

build 23 增加通用 `host.capabilities.webSignInHTML` 与 `host.webSignIn({html})`，限制文档大小、类型及初始页面和 Cookie 目标的 HTTPS 同源条件。在非持久 WKWebView 中运行插件提供的登录文档，错误桥只接受同源顶层页面并限制长度；取消、失败及 WebKit 进程终止均拒绝迟到 Cookie。汽水 0.4.0 在同一浏览器会话中加载官方安全 SDK、初始化 `ttwid`、生成专用二维码并确认登录；沿用本机匿名注册 ID，切到后台暂停轮询、回前台恢复，平台拒绝不自动重试。浏览器返回会话后，插件在线验证账号再保存，旧账号不会被失败尝试覆盖。2026-11-20，用户完成汽水 App 确认后返回山海，已确认登录成功并显示个人歌单。尚未实现额外安全验证 2046 的交互处理，不能推广为所有账号均可免验证登录。

山海 Service 节点的 `/healthz` 正常，`/v1/sessions/bilibili` 返回预期未认证，`/v1/data/bilibili/profile` 返回普通 404；server 分支没有实现 `/v1/data`。因此“节点不支持此同步功能”来自服务端缺少资料同步接口，非密码错误。本轮未修改或部署服务端。

## 验证记录

build 23 的 Swift 全量 176 项通过，包含预加载阈值、取消与迟到结果、切歌缓存复用、过期回退、视频控制状态、旧代理策略迁移，以及新增 HTML 权限/大小/类型/端口、页面失败后迟到 Cookie、汽水浏览器会话和资料断线恢复行为。汽水 Node 23 项、两个脚本语法检查通过；此前 YouTube Node 15 项通过，本次未修改该插件。

已用真实 WebKit 验证官方 SDK 1.0.0.41 加载、`ttwid` 会话初始化、取码及连续三次等待状态，均 HTTP 200、业务码 0。该探针只使用新匿名会话，记录状态码、路径及资源域名，不记录二维码票据、Cookie 或账号；它仅验证匿名阶段，完整授权的依据是用户随后在手机确认成功。build 23 的通用 iOS Simulator 构建与真机 Release 签名构建均通过。

旧后台计时器测试用固定 80ms 后读取，重负载时可能先读取后触发；改为等待真实首个定时事件后验证，消除对机器调度速度的依赖。
