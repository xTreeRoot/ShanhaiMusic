# 山海插件：音视频断点流播适配方案

配套文档：[宿主 App 改造方案](streaming-host.md)。本文记录哔哩哔哩和四个 GitHub 插件的流播契约与历史适配依据，区分现状和待改项。**插件只管拿到可播且可重新解析的资源；不存断点、不代播放器发分段请求、不写第二套播放器。**

## 1. 继续使用现有契约

| 调用 | 插件负责 | 不要求插件做 |
| --- | --- | --- |
| `stream({id, quality})` | 返回宿主可直接读取的合法音频或含音轨的媒体，沿用 `url`、`headers`、`type`、`size`、`bitRate`、`quality` 等已有字段；可选字段没有可信值就省略。 | 不传播放时间，不接 `Range`，不写分段、不解码。 |
| `video({id, quality})` | 有能力才导出；给同一曲目的可播放视频地址和必要请求头，沿用现有 `{url, headers?}`；现有移动适配器能读取 `type`，有真实格式时可提供。 | 不用歌曲 ID 猜 MV，不把封面、试听或音频直链冒充视频。 |
| 同参数再次解析 | 使用同一账户授权与曲目/档位重新获得可播地址；同一轮并发可以合并，完成后移除进行中的条目。 | 不自造备用地址，不承诺每次都换 URL，不为绕过权限而换账号、降成试听或伪造成功。 |

**首版不加必填字段、不加导出函数、不提高最低宿主版本。** 注册、能力发现、请求头和账户存储仍按 [山海插件契约](../plugins/README.md)。不额外返回 `supportsRange`：一个 CDN 返回 `206` 不代表所有内容和所有档位都支持，由宿主按实际响应判断。只有后续明确需要刷新选项、候选地址等跨源能力时，才一起补宿主的可选契约和兼容测试。

## 2. 五个插件分别怎么改

### 外部哔哩哔哩插件：两条 DASH 轨，优先验证同一个 `cid`

- **实现归属**：[独立哔哩哔哩插件](https://github.com/xTreeRoot/mygo-music-bilibili) 负责平台请求、DASH 解析、账号与字幕；三端统一通过插件宿主调用，不再把平台实现编译或嵌入 App。以下流播校验在独立插件仓库执行，宿主只保留通用媒体能力。
- **待改**：保留现有真实接口和请求头。恢复时重新解析同一内容，两条轨都来自同一个 `cid`；对照各端档位选择，确认重取返回实际对应的音频轨和视频编码。若要合并同一轮并发的 `playbackInfo`，只合并同内容、同会话的进行中请求，不缓存失败和已完成的签名结果。不为了传 `cid` 改所有插件协议；平台适配器内部校验即可。
- **待验**：公有样本分别做音轨和视频轨非零 Range、签名重取、分轨解码。若主地址不稳定，才考虑适配器提供经过验证的响应内 `backup_url`；首版不依赖备用地址，不能猜 CDN 域名，也不能拿备用地址相似性判断字节等同。

### YouTube Music `0.1.3`：别把 30 分钟缓存当作刷新

- **现状**：[`index.js`](https://github.com/xTreeRoot/mygo-music-youtube-music/blob/4dd48ff3e1c6be0b6607eb766323a0effd49cdc5/index.js#L814) 音频挑 MP4 内 AAC；视频挑 AVC MP4，可能是独立视频轨或自带音频。音频 `located` 会在 30 分钟内复用已完成结果，视频没有这层结果缓存；音画可以共享进行中的平台响应解析。
- **待改**：把音频已完成的签名地址缓存从 `stream` 的必经路径移除，保留进行中合并；宿主再次调用能重新向平台解析，不命中自己手里的旧链接。先不猜 URL 内的有效期字段。保留原 URL 编码和现有 CDN 请求头；视频没直链时正常报不可用，不把音频可播当成视频可播。
- **待验**：同请求并发只解析一次，第一次结束后再次调用会真正解析；模拟旧 URL 失效后拿到新资源；真实网络分别验可用 AVC、音频 Range 和视频 Range。含音轨视频只允许一个引擎发声，由宿主验证。

### 网易云 `0.1.16`：普通音频和公开 MV 分开处理

- **现状**：[`index.js`](https://github.com/xTreeRoot/mygo-music-netease/blob/fce720a8e3a76799f84d1b37bd951ce1c80e6ff6/index.js#L1029) 对 `mv:` 曲目由 `stream` 转给 `video`，两者拿同一个资源；普通歌曲及播客走独立音频路径。公开 MV 目前返回 `type: "m4a"`（现有测试锁定），播放器从同一个容器取声音和画面。
- **待改**：保留 `mv:` 身份、公开播放校验和同档位并发去重。不要直接把 `stream` 返回类型改成 `mp4`：桌面旧缓存和移动音频路径需要兼容。若实测视频加载器需要 `mp4` 类型，再由同一个底层 MV 结果分别生成音频和视频描述，同地址同请求头；相应回归比较资源是否相同，不再依赖两个返回对象逐字段相等。保持普通 MP3 和无损 FLAC 按平台实际响应区分。
- **待验**：公开 MV 同档位同资源，正常歌曲不调用 MV 地址接口，试听及非公开内容正常拒绝；真实公开 MV 验中间位置同时出声、出画，普通与无损音频分别验非零跳读。

### 汽水 `0.2.2`：只适配完整 AAC/M4A 音频

- **现状**：[`index.js`](https://github.com/xTreeRoot/mygo-music-soda/blob/215df5768a9dc15e86d78de46797209d36dd849d/index.js#L115) 从详情缓存选完整音频，复用详情约 60 秒；现有字段名 `video_model` 只是平台模型名字，不是插件的视频能力。
- **待改**：保留完整时长、域名和格式校验。若媒体地址被详情缓存卡住，`stream` 的媒体解析只复用进行中的请求，字幕和其他详情仍可用原缓存；不改成清空整个插件缓存。不新增 `video`。
- **待验**：同曲目重新取媒体不被旧签名困住，试听仍拒绝，裸 AAC 和 M4A 样本分开跑。某个容器不能任意位置跳读时由宿主降级，不把格式改名冒充可跳。

### 喜马拉雅 `0.1.6`：用长单集验音频，不动云端进度

- **现状**：[`src/playback.js`](https://github.com/xTreeRoot/mygo-ximalaya/blob/b7a50a47da1756cf4a05f30462a720b1c6cf5f19/src/playback.js#L50) 已按曲目、档位、会话合并进行中请求，完成移除；同档优先 MP3，也可选 M4A/AAC/FLAC。已有[公开 Range 探针](https://github.com/xTreeRoot/mygo-ximalaya/blob/b7a50a47da1756cf4a05f30462a720b1c6cf5f19/scripts/smoke.mjs#L24)，初始探针只验证开头 Range。
- **待改**：能满足重新解析就不改业务逻辑，补测试即可。保持完整单集权限与试听校验，不把会话 Cookie 发给音频 CDN。云端历史仍只读，本地时间断点由宿主管理。当前没实现视频，不新增 `video`。
- **待验**：扩展公开探针到非零偏移，核对 `206`、`Content-Range` 和实际长度；游客长单集优先测。已购或登录限制内容必须单独用有权账号验收，不能用游客测试代替。

## 3. 联调与发布顺序

1. **宿主先兼容存量**：用不改签名的旧插件验证顺序播放、恢复时间点和按需读取；向平台请求解析失败不影响其他源。不以插件升级作为旧版正常播放的前置条件。
2. **插件只改实际卡点**：优先处理 YouTube 的旧地址缓存，汽水按复现结果改；B 站核对双轨及原生适配，网易云核对同资源和类型，喜马拉雅先复用。运行各插件现有 Node 测试、产物与旧宿主冒烟；发布前按独立仓库约定核对插件版本及包内入口，安装更新不覆盖用户数据。
3. **真源逐个签收**：音频每家至少留一条非零偏移和断网/重取证据，视频对 B 站分轨、YouTube AVC、网易云公开 MV 各留一组。测试日志只记来源、格式、状态、区间、字节数和最终音画结果，不包含签名 URL 或凭据。没测的档位、登录态和设备标记未验收；基础合约测试通过不代表真实 CDN 已通过。
